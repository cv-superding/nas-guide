# 12.2 那些项目做对了什么

从十几个真实 homelab 项目里，能提炼出几条反复出现的实践。这些是"经过实战检验"的经验，比理论更有说服力。

## 一、备份要自动，还要验证

[jbaznik/homelab](https://github.com/jbaznik/homelab_codeasashu) 的简介里特别写了 "verified nightly backups"（经过验证的每夜备份），并强调系统能防意外数据丢失和断电。

注意"verified"这个词——**备份完还要验证能恢复**，这正是我们在 [5.4](../05-存储与数据保护/5.4-备份3-2-1原则.md) 反复强调的。很多人只做备份不验证，出事时才发现备份是坏的。

> 💡 学这一条：把"恢复演练"放进你的定期任务，而不是想起来才做。

## 二、入口用 Tailscale 收住

[kimzam30/my-homelab-setup](https://github.com/kimzam30/my-homelab-setup) 明确说它的服务"all secured behind a private Tailscale"。[SinghChinmayy/homelab](https://github.com/SinghChinmayy/homelab) 也提到 "optional Tailscale integration for secure remote access"。

这是社区共识：**远程访问用组网 VPN，而不是端口转发**。呼应 [6.2](../06-网络与远程访问/6.2-远程访问方案对比.md)。

## 三、用 Portainer / 界面管理容器

多个项目提到用 [Portainer](https://github.com/portainer/portainer) 管理容器——"All containers are managed through Portainer for easy monitoring, updates, and administration"。

对不想天天敲命令的人，图形界面管理容器确实省心。不过本指南以 Compose 命令行 + 各 NAS 自带的容器界面为主，Portainer 作为可选知道即可。

## 四、媒体自动化是刚需

[SinghChinmayy/homelab](https://github.com/SinghChinmayy/homelab) 描述了一个"complete, automated media management solution"，[TechHutTV/homelab](https://github.com/TechHutTV/homelab) 也是云原生方向。

影音自动化（Sonarr/Radarr/qBittorrent/Jellyfin 那套）几乎是 homelab 的标配玩法，详见 [10.2 影音类](../10-自托管应用图谱/10.2-影音阅读与音乐.md)。

## 五、文档即代码

这些项目都用 README 把架构、服务、恢复步骤写清楚。有的还配架构图。这种"把说明写进仓库"的习惯，让项目即使过几个月回来看也能看懂。

呼应 [8.2 Ansible](../08-进阶主题/8.2-Ansible自动化运维.md) 的"用代码定义配置"理念——配置进 Git，改动可追溯。

## 写在最后

这些实践不是什么高深技术，但都是"用过才知道重要"的东西。尤其是备份验证和 VPN 入口——这两条做到，家庭服务器就稳了大半。
