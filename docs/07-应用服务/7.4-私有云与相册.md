# 7.4 私有云与相册：把网盘搬回家

> 📌 先读：[7.1 Docker 基础](7.1-Docker基础.md)、[6.4 HTTPS](../../docs/06-网络与远程访问/6.4-HTTPS与证书.md) · ⏱ 大约 15 分钟

## 先选对工具

不同需求对应不同工具，别装错了：

| 需求 | 方案 | 特点 |
| --- | --- | --- |
| 文件 + 协作 + 日历 | Nextcloud | 功能全面，像自建网盘 |
| AI 相册（人脸、聚类） | Immich | 现代、体验接近大厂相册 ✅ |
| 轻量同步 | Syncthing | 去中心化，见 [7.3](7.3-下载与同步.md) |
| 厂商相册 | 群晖 Photos / 飞牛相册 | 简单，跟系统整合 |

> 💡 只想自动备份手机照片、要好看的时间线和人脸聚类？直接上 **Immich**。需要在线文档、日历、分享链接这种"网盘全套"？选 **Nextcloud**。

## Nextcloud：自建网盘

功能：文件存储、在线文档、日历、联系人、分享链接等。

部署示例在 [`examples/docker-compose/nextcloud/`](../../examples/docker-compose/nextcloud/docker-compose.yml)——它包含应用和数据库（MariaDB）两个容器。

关键配置：

- 数据库和 data 目录**都要持久化**，否则删容器数据就没了
- 公网访问必须配 HTTPS，见 [6.4](../../docs/06-网络与远程访问/6.4-HTTPS与证书.md)
- 它对硬盘随机 IO 敏感，放 SSD 或加缓存会明显更顺

> ⚠️ Nextcloud 比较"重"，低配机器会吃力。只想备份照片的话，Immich 或厂商 App 更合适——别为了"功能全"给自己找麻烦。

常见小坑：

- **上传大文件失败**：检查反代的 body size 限制和 PHP 上传限制
- **访问慢**：多半是硬盘 IO 或没开缓存，见 [8.3](../../docs/08-进阶主题/8.3-性能调优.md)
- **分享链接打不开**：确认域名和 HTTPS 配对了

## Immich：AI 相册

功能：照片/视频备份、人脸聚类、时间线、地图、共享相册，手机 App 能自动备份。体验上很像某大厂相册，但数据在你自己家。

配置示例在 [`examples/docker-compose/immich/`](../../examples/docker-compose/immich/docker-compose.yml)（简化版，生产用请按官方补全 Redis、machine-learning 等服务）。

要点：

- 需要 PostgreSQL 数据库，同样要持久化
- 人脸聚类、智能识别这些功能比较吃内存
- 资源紧张的话可以关掉 AI 功能，只留备份和时间线

> 💡 手机 App 记得设"仅 WiFi 备份"并给它后台运行权限，否则可能悄悄停止备份——这是很多人以为"备份好了"其实没有的坑。

## 顺带说说密码管理

很多人也在 NAS 上自托管密码管理器（比如 Vaultwarden，Bitwarden 的轻量替代）。这属于"高敏感"服务：

> ⚠️ 密码库必须 HTTPS + 强主密码 + 2FA，并做好备份。一旦数据丢了，所有密码都没了。示例在 [`examples/docker-compose/vaultwarden/`](../../examples/docker-compose/vaultwarden/docker-compose.yml)。

初始化后记得关掉注册（`SIGNUPS_ALLOWED=false`），别让外人建账号。

## 安全别忘了

- 公网暴露的服务都要 HTTPS + 强密码 + 2FA
- 分享链接设有效期和密码，别做成永久公开
- 镜像勤更新，见 [6.5 安全加固](../../docs/06-网络与远程访问/6.5-安全加固.md)
- 定期做恢复演练，见 [5.4](../../docs/05-存储与数据保护/5.4-备份3-2-1原则.md)

## 写在最后

Nextcloud 适合全面私有云，Immich 专注 AI 相册。按需求挑一个，别部署一堆用不上的。公网访问务必 HTTPS，数据务必另外备份。

## 动手试试

1. 部署 Immich 或 Nextcloud 其一，测一次手机自动备份。
2. 给它配 HTTPS，确认浏览器显示安全锁。
3. 从备份恢复一张测试照片，验证数据真的留得住。
