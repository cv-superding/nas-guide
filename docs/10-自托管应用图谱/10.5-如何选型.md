# 10.5 怎么挑一个自托管应用

> 这一节是全章的"方法论"——清单会过时，选型心法不会

## 先别急着装

清单看得越多，越容易犯一个错：**看到什么都想装。**

[awesome-selfhosted](https://github.com/awesome-selfhosted/awesome-selfhosted) 收录了 1000+ 项目，[Self-Hosting-Guide](https://github.com/mikeroyal/Self-Hosting-Guide) 的 README 有 7000+ 行。但没人真能用完它们。

挑应用之前，先问自己三个问题：

1. **它解决我的什么具体问题？**（说不出具体问题，就别装）
2. **我会用多久？**（"试试看"往往等于吃灰）
3. **有没有更简单的方案？**（一个脚本能搞定的，就别上完整应用）

## 选型五步法

```mermaid
flowchart LR
    A[1 明确需求] --> B[2 查候选]
    B --> C[3 看维护状态]
    C --> D[4 小范围试装]
    D --> E[5 决定去留]
```

### 1. 明确需求

用一句话写下来："我想要 ___，因为 ___"。写不出来就先别动。

### 2. 查候选

到 awesome 类清单里按场景找，通常能找到 2～3 个候选。看看它们的官网说明和截图。

### 3. 看维护状态

这一步很多人跳过，但很重要。打开 GitHub 仓库看：

- 最后一次提交是什么时候？（超过一两年没动静要谨慎）
- Issue 有没有人回？（维护者还在不在）
- Star 数和 Fork 数（活跃度的间接信号）
- 许可证（是不是你能接受的）

> 💡 awesome-selfhosted 用 ⚠ 标记"依赖专有/第三方服务"的项目，遇到这种标记多留个心眼。

### 4. 小范围试装

别一上来就正式用。在一个隔离环境里装起来，用几天：

- 数据卷映射对吗？
- 资源占用能接受吗？
- 和现有服务冲突吗？
- 备份怎么做？

### 5. 决定去留

几天后回头看：真用上了就留下并配置好备份；没用上就果断删掉，释放资源。

## 一个决策清单

每次装新应用前，对着勾一遍：

- [ ] 我能说清它解决什么问题
- [ ] 我确认过它还在维护
- [ ] 我知道它的数据存在哪儿、怎么备份
- [ ] 我清楚它要不要暴露公网、怎么保护
- [ ] 我了解它的资源占用
- [ ] 我有"试几天再决定"的计划

## 常见的坑

> ⚠️ **坑 1：装了不用的服务越积越多**，最后拖慢机器、增加攻击面。定期清理"僵尸服务"。
>
> ⚠️ **坑 2：不看许可证就用**。有些项目对个人免费、商用收费；有些有使用限制。
>
> ⚠️ **坑 3：把测试环境当生产用**。试装时的数据没持久化，正式用时才发现丢数据。
>
> ⚠️ **坑 4：盲目追新**。刚发布的项目可能 bug 多、文档少，等稳定一点再上更稳。

## 写在最后

自托管最大的敌人不是技术，是"收集癖"。这张图谱是地图，不是购物清单。带着问题来，解决问题就走。

1. 从前面四节圈出 3 个候选应用，用五步法逐个评估。
2. 最后只留下一个——先把它用扎实。
