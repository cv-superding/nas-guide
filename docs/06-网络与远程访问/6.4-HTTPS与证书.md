# 6.4 HTTPS：给访问加一把锁

> 📌 先读：[6.3 反向代理](6.3-反向代理与域名.md) · ⏱ 大约 12 分钟

## 为什么非要 HTTPS

明文 HTTP 传密码和数据，就像明信片——路上谁都能看。

HTTPS 做三件事：

- **加密**：内容不被偷看
- **完整性**：不被中途篡改
- **可信**：浏览器验证网站身份，地址栏那把小锁

NAS 管理界面、自托管服务如果要从公网访问，务必上 HTTPS。

## 证书从哪儿来

| 类型 | 说明 | 适合 |
| --- | --- | --- |
| Let's Encrypt | 免费、自动续期、受信任 | 有域名的公开服务 ✅ |
| 自签名 | 免费、自己签发 | 纯内网 |
| 商业证书 | 付费 | 企业 |

## 方案一：Let's Encrypt（推荐）

通过反向代理自动申请和续期：

- **Nginx Proxy Manager**：代理主机设置里一键申请
- **Caddy**：配好域名自动申请，几乎零配置
- **Traefik**：也是自动的

需要域名解析到你的服务器，并通过验证。没有公网 IP 时可以用 **DNS-01 验证**（通过 API 自动加 DNS 记录），配合 Cloudflared 这类工具很流行。

## 方案二：自签名（纯内网）

只在家里用可以自己签一个，但浏览器会提示"不安全"，需要手动信任。公网服务请务必用受信任的证书。

```bash
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout nas.key -out nas.crt \
  -subj "/CN=nas.local"
```

## 启用之后要做的事

1. 设置 HTTP 自动跳转 HTTPS
2. （谨慎）开 HSTS——设置后浏览器会强制 HTTPS，配错会访问不了
3. 把所有访问链接改成 `https://`

## 证书维护

- Let's Encrypt 证书 90 天有效，**务必配自动续期**
- 盯一下到期时间，见 [8.5](../../docs/08-进阶主题/8.5-监控与告警.md)
- 私钥别提交到仓库（`.gitignore` 已经排除了）

## 写在最后

有域名就用 Let's Encrypt + 自动续期；纯内网可用自签名。启用 HTTPS 后记得强制跳转，并盯着证书有效期。

## 动手试试

1. 给一个服务启用 HTTPS，用浏览器确认出现安全锁。
2. 检查自动续期是不是配好了。
