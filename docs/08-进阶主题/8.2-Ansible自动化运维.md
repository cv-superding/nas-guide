# 8.2 Ansible：让重复的事，自己做

> 📌 先读：[7.1 Docker 基础](../../docs/07-应用服务/7.1-Docker基础.md) · ⏱ 大约 18 分钟

## 想象一个"录音版的你"

手动配 NAS 是什么体验？装包、建目录、改配置、起服务……一台机器敲一遍，换台机器再来一遍。敲多了，人会不会疯？

Ansible 就像把你的操作"录"下来，写成一份剧本（Playbook）。以后让它照着演一遍就行。而且它有个很贴心的地方——**幂等性**：同样的剧本跑两次，第二次不会把第一次的成果搞乱，只会确认"已经对了"。

这正是 [Ansible-NAS](https://github.com/) 这类项目背后的理念：**用代码定义你的 NAS**。

## 先认识几个词

| 词 | 大白话 |
| --- | --- |
| Inventory | 你要管哪几台机器（名单） |
| Playbook | 你要它们做什么（剧本，YAML 写的） |
| Task | 剧本里的一个个动作 |
| Module | Ansible 内置的动作工具（装包、建目录等） |

## 动手写第一个剧本

```bash
# 装 Ansible（在你自己的电脑上，不是 NAS 上）
pip install ansible

# 写一份主机名单
cat > inventory.ini <<'EOF'
[nas]
nas-home ansible_host=192.168.1.10 ansible_user=admin
EOF
```

然后写 `setup.yml`：

```yaml
- name: 基础环境配置
  hosts: nas
  become: true
  tasks:
    - name: 装几个常用工具
      package:
        name: [curl, vim, smartmontools, rsync]
        state: present

    - name: 建 Docker 目录
      file:
        path: /volume1/docker
        state: directory
        mode: '0755'

    - name: 确保时间同步在跑
      service:
        name: systemd-timesyncd
        state: started
        enabled: true
```

执行：

```bash
# 先演练，看看会做什么（不改系统）
ansible-playbook -i inventory.ini setup.yml --check

# 确认没问题，真跑
ansible-playbook -i inventory.ini setup.yml
```

> 💡 `--check` 是个好习惯。先看它打算干嘛，再放行。

完整例子在 [`examples/ansible/`](../../examples/README.md)。

## 几个过来人的建议

- 从小任务开始：先 automating 装包、建目录这种简单的
- Playbook 放进 Git，改了什么一清二楚
- 密码别明文写，用 Ansible Vault 加密
- 别一上来就 orchestration 一大堆容器，先把思路跑通

## 写在最后

Ansible 让配置从"手动点"变成"代码管"。好处是可重复、可追溯、不会漏步骤。从一件小事开始，慢慢把重复劳动都交出去。
