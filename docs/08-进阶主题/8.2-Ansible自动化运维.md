## 本章目标

- 理解 Ansible 的用途与核心概念
- 能编写简单的 Playbook 自动化配置任务

## 为什么需要自动化

手动操作的问题：重复、易错、不可复现、无法记录。Ansible 用"代码"描述期望状态，让配置变得：

- **可重复**：一台和多台机器执行同样配置
- **可版本化**：配置进 Git，改动可追溯
- **幂等**：重复执行不会破坏已配置好的状态

> 💡 这类"用代码定义 NAS"的思路，正是 Ansible-NAS 等项目的核心理念。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| Inventory | 要管理的主机清单 |
| Playbook | YAML 格式的任务剧本 |
| Task | 单个操作（装包、建目录、改配置） |
| Module | Ansible 内置的操作单元（apt、copy、service 等） |
| Idempotency | 幂等性：重复执行结果一致 |

## 安装与清单

```bash
# 安装 Ansible（控制端）
pip install ansible

# inventory.ini 示例
cat > inventory.ini <<'EOF'
[nas]
nas-home ansible_host=192.168.1.10 ansible_user=admin
EOF
```

## 第一个 Playbook

```yaml
# setup.yml
- name: 基础环境配置
  hosts: nas
  become: true
  tasks:
    - name: 安装常用工具
      apt:
        name:
          - curl
          - vim
          - smartmontools
        state: present
        update_cache: true

    - name: 创建 Docker 目录
      file:
        path: /volume1/docker
        state: directory
        mode: '0755'

    - name: 确保 Docker 服务运行
      service:
        name: docker
        state: started
        enabled: true
```

执行：

```bash
ansible-playbook -i inventory.ini setup.yml
```

## 部署容器（示例）

```yaml
- name: 部署 Jellyfin
  hosts: nas
  tasks:
    - name: 创建配置目录
      file:
        path: /volume1/docker/jellyfin/config
        state: directory

    - name: 启动 Jellyfin 容器
      docker_compose:
        project_src: /volume1/docker/jellyfin
        state: present
```

> 💡 完整示例见 [`examples/ansible/`](../../examples/README.md)，包含基础环境与容器部署的 Playbook。

## 实践建议

- 从"小任务"开始：先自动化装包、建目录
- Playbook 进 Git，配合 GitOps 思路
- 用 `--check` 先演练：`ansible-playbook --check setup.yml`
- 敏感数据用 Ansible Vault 加密，不要明文写密码

## 小结

Ansible 让 NAS 配置从"手动点"变成"代码管理"。从小任务入手，逐步把重复操作自动化，享受幂等与可复现的好处。

## 练习

1. 写一个 Playbook，自动安装 smartmontools 并创建 docker 目录。
2. 用 `--check` 模式演练，确认无误后再实际执行。
