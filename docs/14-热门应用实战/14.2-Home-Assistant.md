# 14.2 Home Assistant：把家串起来

## 它解决什么问题

如果你家里有智能灯泡、插座、传感器、扫地机器人……它们往往各有一个 App。Home Assistant（HA）把这些设备**统一到一个界面**，还能做自动化："有人回家自动开灯""温度高了开空调"。

它可以装在 NAS 的 Docker 里，也可以装在树莓派或独立主机上。装在 NAS 上省一台机器，但它比较吃资源，而且涉及蓝牙/USB 设备时可能需要直通。

## 部署

示例在 [`examples/docker-compose/home-assistant/docker-compose.yml`](../../examples/docker-compose/home-assistant/docker-compose.yml)：

```yaml
version: "3.8"
services:
  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    container_name: homeassistant
    restart: unless-stopped
    privileged: true
    network_mode: host
    environment:
      - TZ=Asia/Shanghai
    volumes:
      - /volume1/docker/home-assistant:/config
      - /etc/localtime:/etc/localtime:ro
```

关键点：

- **`network_mode: host`**：HA 需要发现局域网设备（如 ESPHome、部分 IoT），用 host 网络模式才能正常工作
- **`/config` 持久化**：所有配置、自动化脚本都在这里，必须映射出来
- `privileged: true`：部分集成需要，但也有安全代价；能不用时尽量不用

> ⚠️ host 网络和 privileged 都提升了权限。只在你信任的家庭网络里这么用，别暴露公网。

## 首次配置

1. 浏览器访问 `http://<NAS的IP>:8123`
2. 创建账号，设置位置（用于天气、日出日落等）
3. 系统自动扫描局域网设备，按提示添加集成
4. 进入"设置 → 设备与服务"手动添加更多集成

> 💡 国内用户常用的米家、HomeKit 等集成需要额外配置（有的需要 token，有的通过 HACS 装插件）。这部分社区资料很多，见 [致谢](../../CREDITS.md) 与 [Home Assistant 官网](https://www.home-assistant.io/)。

## 实测验证

1. 打开 HA 界面，能看到至少一个设备（哪怕是自己加的一个虚拟开关）
2. 建一条简单自动化：比如"每天 22:00 推送通知"
3. 重启容器，确认 `/config` 里的设备、自动化都还在

## 资源占用提醒

HA 本身不算重，但装上 HACS、各种集成和数据库后，内存和 CPU 占用会慢慢涨。如果 NAS 还要跑别的重负载服务，可以考虑：

- 给容器设内存上限
- 关掉用不到的集成
- 或者把 HA 挪到单独的小主机/树莓派上（见 [3.7](../03-平台横评与选型/3.7-树莓派与软路由.md)）

## 远程访问

和别的自托管服务一样：优先用 Tailscale/VPN，别直接端口转发。见 [6.2](../06-网络与远程访问/6.2-远程访问方案对比.md)。HA 官方也提供云端远程方案，但那是付费服务，按需选择。

## 写在最后

Home Assistant 是"智能家居的中枢"，能力极强但水也深。装在 NAS 上可行，记得用 host 网络、持久化 config、注意权限。

## 动手试试

1. 部署 HA，完成首次配置。
2. 添加至少一个设备或虚拟实体，建一条简单自动化。
