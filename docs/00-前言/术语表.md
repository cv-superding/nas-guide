# 名词表（遇到天书就回来翻）

  <img src="../assets/images/ch01-know-nas.png" alt="从乱糟糟的数据开始认识" width="200">

第一次看 NAS 教程，最劝退的往往不是操作，是满屏的缩写。这里按主题把常见词收在一起，用大白话解释。不用背，来回查就行。

> 中文里常中英混着说，比如"做个 RAID""开个 SMB"。知道它们大概指什么，就够了。

## 最基础的几个

| 你会看到的词 | 说人话 |
| --- | --- |
| NAS（网络附属存储） | 一台连在网上、专门存东西的小电脑 |
| 共享文件夹 Shared Folder | 从这台小电脑上"分"出来、大家都能访问的目录 |
| SMB / NFS / AFP | 不同系统之间传文件的"语言"，Windows 爱用 SMB，Linux 爱用 NFS |
| 用户 / 用户组 | 决定谁能进、谁能改的身份卡片 |
| 权限 ACL | 具体到"谁能读、谁能写"的规矩 |
| NTP | 对时的，让所有设备时间一致 |

## 硬盘那些事

| 词 | 说人话 |
| --- | --- |
| HDD / SSD | 机械硬盘（大、便宜、有声音）/ 固态硬盘（快、静音、贵） |
| RAID | 把几块盘组合起来，坏一块不至于全丢 |
| 存储池 Storage Pool | 几块盘先攒成一大"池"水，再从池里舀出空间用 |
| 卷 Volume / 数据集 Dataset | 从池里划出来的实际可用空间 |
| 热备盘 Hot Spare | 平时闲着，谁坏了它顶上 |
| S.M.A.R.T. | 硬盘的"体检报告"，能看出它是不是快不行了 |
| 坏道 Bad Sector | 盘上读不出来的小格子 |
| CMR / SMR | 两种记录方式，做 RAID 尽量选 CMR（SMR 重建慢且危险） |

## 文件系统的"超能力"

| 词 | 说人话 |
| --- | --- |
| 文件系统 | 硬盘上"怎么摆数据"的规矩，ext4/Btrfs/ZFS 是不同流派 |
| 快照 Snapshot | 给数据在某一刻拍张照片，删错了能"穿越"回去 |
| 校验和 Checksum | 给数据盖个指纹，读的时候验证有没有悄悄变坏 |
| CoW（写时复制） | 改数据先写新地方再改指向，更安全，也更容易做快照 |
| scrub | 主动给数据"体检"，发现坏味道就修 |
| 3-2-1 备份 | 3 份数据、2 种介质、1 份放外地——经典保命法则 |

## 网络和访问

| 词 | 说人话 |
| --- | --- |
| IP 地址 | 设备在家里的门牌号 |
| DDNS | 门牌号老变？给它绑个固定名字 |
| 端口转发 | 把路由器的某个门口指向家里某台机器（慎重开） |
| 内网穿透 | 没公网 IP 也能从外面摸进来 |
| 反向代理 | 一个总台，按你说的话把请求转给不同服务 |
| VPN / Tailscale | 给外网访问加一条加密隧道，像配了把钥匙 |
| HTTPS / TLS | 上网时给数据上锁，浏览器那个小锁图标 |
| 网关 Gateway | 通往别的网络的出口 |

## Docker 与应用

| 词 | 说人话 |
| --- | --- |
| 容器 Container | 一个轻量的、装好应用的小隔间 |
| 镜像 Image | 做小隔间的模板 |
| Docker Compose | 一个配置文件，一口气定义好几个小隔间 |
| 数据卷 Volume | 隔间外面的储物柜，隔间拆了东西还在 |
| 虚拟机 VM | 一整套模拟出来的电脑，比容器重 |
| Root / 特权模式 | 最高权限，能不用就不用 |
| Ansible | 用脚本代替手点，让配置能重复、能回溯 |

## 自托管与清单

第 10 章会碰到这些词：

| 词 | 说人话 |
| --- | --- |
| Self-hosting（自托管） | 把软件跑在自己的机器上，而不是用厂商的在线服务 |
| SaaS | 软件即服务——厂商托管，你租着用，数据在厂商那边 |
| Awesome List | GitHub 上"精选清单"类仓库的统称，通常叫 `awesome-xxx` |
| 反特性标记 ⚠ | 清单里提示"依赖专有/第三方服务、不算完全独立"的标记 |
| 技术栈标签 | 清单条目末尾的 Docker / Go / PHP 等，表示实现方式和部署类型 |
| Homelab | 在家里搭的实验室环境，用来跑各种自建服务 |
| AIO（All in One） | 一台机器跑所有东西，灵活但故障影响面大 |
| 文档即代码 | 把架构、配置、恢复步骤写进仓库，跟代码一起管理 |

## 虚拟化底层

第 11 章会碰到这些词：

| 词 | 说人话 |
| --- | --- |
| 虚拟化 | 把一台物理电脑"切"成多台虚拟电脑 |
| Hypervisor | 管理虚拟机的那一层（PVE 就是） |
| KVM | Linux 上的完整虚拟化技术，跑完整虚拟机 |
| LXC | 轻量容器，共享宿主内核，比虚拟机省 |
| 宿主机 Host | 跑虚拟机的那台物理机器 |
| 客户机 Guest | 跑在宿主机里的虚拟机 |
| PCIe / 设备直通 | 把物理硬件直接交给某台虚拟机独占使用 |
| IOMMU | 支持直通的硬件基础（Intel 叫 VT-d，AMD 叫 AMD-Vi） |
| vmbr0 | PVE 默认的网络网桥，虚拟机靠它连局域网 |
| q35 / OVMF | 虚拟机的机型和 UEFI BIOS 类型，PVE 建 VM 时常见选项 |

## 一句话辨析

光看词可能还绕，这里放几个最容易被搞混的：

- **快照 ≠ 备份**：快照和原数据在同一台机器上，机器没了它也没了。
- **同步 ≠ 备份**：你删一份，另一端也跟着删；备份要能回到过去。
- **RAID ≠ 备份**：RAID 防的是坏盘，防不了误删和火灾。
- **重启 ≠ 重装**：很多问题重启就好，别动不动就重装系统。
- **虚拟机 ≠ 容器**：前者是完整电脑，后者是共享内核的小隔间，见 [8.1](../../docs/08-进阶主题/8.1-虚拟机与容器.md)。
- **同步 ≠ 备份**：在 homelab 里尤其容易混——同步让文件一致，备份让你能回到过去。

想知道为什么，去 [5.3 快照](../../docs/05-存储与数据保护/5.3-快照与版本管理.md) 和 [5.4 备份](../../docs/05-存储与数据保护/5.4-备份3-2-1原则.md) 慢慢看。
