## 本章目标

- 理解各核心部件对 NAS 的实际影响
- 能按用途给出合理的配置倾向

## CPU：够用就好，但要看用途

| 用途 | CPU 要求 | 说明 |
| --- | --- | --- |
| 文件存储/备份 | 低功耗双核/四核 | 大部分时间闲置，节能优先 |
| 影音（含转码） | 带硬件编解码的核显（如 Intel Quick Sync） | 4K/HDR 转码时差异巨大 |
| Docker 多服务 | 四核以上 | 容器多时更从容 |
| 虚拟机 | 多核多线程 | 取决于要跑几个系统 |
| 本地 AI 推理 | 大内存 + 可选独显 | 多数蒸馏模型吃内存多于 CPU |

> 💡 **经验**：家庭 NAS 最常见的"性能浪费"是买了强力 CPU 却只存照片。反过来，最常见的"性能后悔"是没核显却要转码 4K。先想清楚用途。

### 平台选择

- **x86（Intel/AMD）**：生态最广，Docker、虚拟机、AI 支持最好，本指南主力推荐。
- **ARM（树莓派等）**：功耗极低，但软件生态与性能受限，适合轻量场景。见 [3.7 树莓派与软路由](../03-平台横评与选型/3.7-树莓派与软路由.md)。

## 内存：宁多勿少

| 场景 | 建议容量 | 说明 |
| --- | --- | --- |
| 纯存储 | 2～4 GB | 够用 |
| Docker + 影音 | 8 GB | 主流甜点 |
| 虚拟机 / ZFS | 16 GB 起 | ZFS 缓存较吃内存 |
| 本地 AI | 16～64 GB | 模型大小决定需求 |

> ⚠️ **注意**：某些系统（如 TrueNAS with ZFS）对内存较敏感， ECC 内存更稳妥。家用不必强求 ECC，但请选择可靠品牌并留有余量。

## 主板 / 整机

- **盘位数量**：主板 SATA 口数量决定能接多少硬盘；不够可用 HBA 卡扩展。
- **M.2 插槽**：适合做系统盘或缓存/高速池。
- **网口**：至少 1 个千兆；预算允许上 2.5G 更从容。
- **ITX vs MATX vs ATX**：盘位多、扩展多，MATX/ATX 更合适；追求小体积选 ITX。

## 网卡与网络

> 💡 对内传输速度的瓶颈常常不是硬盘，而是网络。一个 2.5G 网口 + 支持 2.5G 的交换机/路由器，能显著提升大文件传输体验。详见 [6.1 局域网基础](../06-网络与远程访问/6.1-局域网基础.md)。

## 其他

- **电源**：选择可靠品牌，额定功率留余量；硬盘启动瞬间电流较大。
- **机箱**：注意风道与硬盘架减震，噪音很大程度来自机箱共振。
- **UPS（不间断电源）**：对数据安全有意义，可配合实现安全关机。见 [5.4 备份 3-2-1 原则](../05-存储与数据保护/5.4-备份3-2-1原则.md)。

## 小结

CPU 看用途、内存宁多勿少、网口尽量快、电源机箱别省钱。记住：硬盘和网络往往比 CPU 更影响体验。

## 练习

1. 根据你的用途，写下 CPU、内存、网口三项的初步要求。
2. 查一下你现有电脑的 CPU 是否带硬件转码能力（搜索"CPU 型号 + Quick Sync / 核显 编解码"）。
